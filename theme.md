# Contract theme plan

Working notes for re-theming the Contract (Eastercon 2028) site. Written so work can resume after a DDEV restart.

## Current state (as of 2026-09-19)

- The dev site was refreshed from the live backups in `live/` (`eastercon2028_drupal.sql.gz` and `.tar.gz`). The dev database was dropped and replaced, `drush updb` reported no pending updates, and `files/` was extracted into `web/sites/default/files` (skipping the `php`, `css` and `js` cache directories). Dev theme code was not overwritten.
- The live default theme is `contract` (on live, `web/themes/contract`), a subtheme of Mercury (`base theme: mercury`). Admin theme is Gin.
- `registration_theme` (`web/themes/contrib/registration_theme`) is installed in code but **not enabled**. It is a plain-CSS base theme with `--rt-*` design tokens, page regions (header, primary menu, page title, breadcrumb, footer regions) and ConReg form styling (`css/components/register-form.css`, `content-tables.css`). It ships no single-directory components (SDCs).
- Mercury's `CUSTOMIZING.md` says not to subtheme it (no backwards compatibility). Its components are styled with Tailwind, built into `build/main.min.css`.
- Claude Code runs inside the DDEV web container, so `ddev` is unavailable there; use `vendor/bin/drush` directly.

## Decisions made

1. **Three-layer theme structure** (agreed 2026-09-19), replacing the earlier plan of basing `contract` directly on `registration_theme`:

   ```
   registration_theme          (contrib, untouched: tokens, page regions, ConReg forms)
     └─ registration_canvas_theme   (site/themes/, generic Canvas layer)
          └─ contract              (site/themes/, Contract branding)
   ```

   - **`registration_canvas_theme`** (base theme: `registration_theme`): generic Canvas-ready SDCs (`heading`, `section`, `text`, `button`, `card-logo`, `navbar`), Canvas region/page templates, and the server-side heading first-word/syllable wrapping. Uses `--rt-*` tokens only, no brand colours or fonts. Reusable by other Canvas sites.
   - **`contract`** (base theme: `registration_canvas_theme`): brand-blue token `#007ca9`, Westminster/Caladea fonts and the heading effect styling, the logo, `hero_logo`, and anything only meaningful for Contract.
   - Re-basing `contract` is still dev-only and **awaiting the user's final go-ahead**.
2. **Vanilla CSS, no Tailwind.** Components use plain CSS with `--rt-*` tokens and a prefixed class naming scheme (`.c-<name>`, assumed to carry over unchanged to the shared components; confirm if a different prefix is wanted). No build step. More components will be added over time, so this must stay simple.
3. **Generic components are built in `eastercon2028.org/eastercon2028_drupal/site/themes/registration_canvas_theme/components/<name>/`** (`.component.yml`, `.twig`, `.css`), replacing the Mercury ones. Contract-only components stay in the `contract` theme's `components/`.
4. **The heading effect is split across the layers:** `registration_canvas_theme`'s `heading` component does the server-side wrapping and outputs the lead text in a `.c-heading__lead` span, unstyled by default. `contract` adds Westminster, Caladea and `#007ca9`.
5. **Move `contract` to `eastercon2028.org/eastercon2028_drupal/site/themes/contract`** as part of re-basing, per AGENTS.md (it currently lives at `web/themes/contract`).

## Heading effect (page titles and main headings)

Mimics the logo (`assets/Contract.svg`): the start of the heading in Westminster, the rest in Cambria bold italic, in the logo blue **`#007ca9`** (the logo's ellipse fill; the logo text itself is white).

- Do it **server-side** (a PHP preprocess or Twig filter that wraps the letters in a `<span>`), not JavaScript. CSS cannot select "the first 3 letters"; the colour itself is plain CSS. JavaScript only as a fallback for headings typed into free-text body fields.
- Rule:
  1. **Multi-word headings:** wrap the whole first word (including apostrophes and hyphens, so `WHAT'S on`, not `WHA/t's on`).
  2. **Single-word headings:** wrap the first syllable using a simple vowel-group rule (below).
  3. **Very long first word** (over about 8 letters) in a multi-word heading: use the syllable rule on it too.
- Syllable rule (approximate is fine):
  - One vowel group in the word: take the whole word.
  - One consonant before the next vowel group: split before it (`Ho|tel`, `Re|gistration`).
  - Two or more consonants: split after the first, keeping digraphs together (`sh ch th ph wh ck ng`): `Hil|ton`, `Con|tract`.
- Fonts:
  - Westminster: `assets/Westminster.ttf`. Its licence does not allow web embedding (see step 4); Bitwise/Aldrich are used instead.
  - Italic part: `font-family: Cambria, Caladea, Georgia, serif`. Windows users with Cambria get it; everyone else gets Caladea (open licence, metric-compatible), self-hosted in four styles. Files need fetching from the Caladea project or Google Fonts; check network access first. Copies of `cambria*.ttf` are in `assets/` but must not be redistributed on the web.
  - Open question: whether the rest of each heading is italic as in the logo, or only the first letters are Westminster (the user replied "sounds good" to the plan, which assumed the logo style).
- **Slide-in (2026-10-09, user request, after the animated logo):** as each heading with a `.c-heading__lead` scrolls into view, the lead slides in from the left and the italic rest from the right. `contract/heading-motion` library (attached in `contract.info.yml`): `css/component/heading-motion.css`, `js/heading-motion.js` (IntersectionObserver behaviour, adds `.is-revealed`), and `js/heading-motion-init.js` (a separate `header: true` library, puts `.contract-heading-motion` on `<html>` before first paint so headings start hidden rather than flash). No markup change: the whole heading moves from `+distance` and the lead, an inline-block, a further `-2 × distance`. Tunable on `:root`: `--contract-heading-motion-distance` (2.5em; was 1.5em, widened at the user's request), `-duration` (0.8s), `-easing`. Off for `prefers-reduced-motion` and without IntersectionObserver; if the behaviour never runs, the init script un-hides headings 1s after `load`. Checked in Selenium on `/code-conduct` (mid-flight and settled, and a heading revealed on scroll). **Stagger (2026-10-09, user request):** headings revealed together are sorted top to bottom and each starts 150ms (`STAGGER` in `heading-motion.js`) after the previous one, through `--contract-heading-motion-delay`; the queue also spaces out headings revealed by a fast scroll. Checked on `/code-conduct`: the three headings in view on load got 0, 150 and 300ms. The animated logo SVG itself was not on disk, so timing is not matched to it.
